# Social Media Manager: Checklist

## Before starting
- [ ] Account list confirmed with handles and who holds each login
- [ ] Period goal written (enquiries, niche followers, authority) with the audience named
- [ ] Approved pillars available, or default pillar mix stated as an assumption
- [ ] This week's source assets listed, with client permission status for each client item
- [ ] Kiran's filming and posting time for the week recorded
- [ ] Scheduling tool identified and confirmed to support a draft or for-review state per network
- [ ] Last week's report read and its "test" item carried into this week

## While working
- [ ] Calendar extended, not rebuilt; covers at least the next 10 days
- [ ] Each calendar row has exactly one owner and a due date
- [ ] Repurposing plan maps atoms to platforms; no full-asset copy-paste
- [ ] No more than 2 posts from the same asset on the same day
- [ ] Promotional rows at or under 15% across the rolling 4 weeks
- [ ] Time-sensitive rows (festivals, admissions season, offers) tagged with an expiry date
- [ ] Every price, offer, date or result traced to a brief or connector value
- [ ] Platform format for each row exists today (checked against a dated source, not memory)
- [ ] Drafts passed `editor` or `proofreader` before entering the approval list

## Before handoff
- [ ] Approval list sent to Kiran as one batch with final text and asset links
- [ ] Only rows with a recorded approval reference are staged
- [ ] Staged posts are in review or draft state; tool post IDs recorded in the calendar
- [ ] Scheduled times are in the future and in IST; links open; alt text present
- [ ] `community-manager` told what is going out and which questions to expect
- [ ] Weekly report leads with enquiries, cites data source and pull date, lists data gaps
- [ ] Report ends with one keep, one stop, one test with a review date
- [ ] Assumptions, open questions and risks listed
- [ ] Handoff written in `orchestration/handoff-format.md` format with evidence

## Stop and escalate if
- [ ] The only scheduling option for a network is live publishing
- [ ] A post shows client work, names or screenshots without a permission record
- [ ] Someone asks to buy followers, join an engagement pod or automate likes or follows
- [ ] A complaint or incident is active on the account while posts are queued
- [ ] A row needs ad spend or a boost
