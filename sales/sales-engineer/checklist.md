# Sales Engineer: Checklist

## Before starting
- [ ] Discovery notes read; every technical need listed in the prospect's own words
- [ ] Decision maker and demo audience known (owner only, manager, technical person)
- [ ] Portfolio inventory available: built projects with links or repo paths
- [ ] Prospect's current setup captured: site, hosting, domain registrar, software in use, data format
- [ ] Any request for unpaid custom work flagged to `account-executive` and the owner

## While working
- [ ] Each requirement has a priority (must, should, nice) and a coverage rating
- [ ] Every "Built" rating cites a real project link or path
- [ ] Weighted coverage computed and must-have gaps counted
- [ ] Recommendation stated: proceed, phase or decline, with the reason
- [ ] Every third-party service has account owner, payer, lead time and risk
- [ ] Gateway, WhatsApp, SMS and API facts checked on the provider's current official page, with date
- [ ] Proof type chosen from the table; pilot scope sentence written if a sprint is proposed
- [ ] Demo script limited to the top three pains and 15 minutes
- [ ] Demo tested at 360 to 412 px width and on throttled 4G
- [ ] Demo uses seeded data; no real client, student or patient records visible
- [ ] Offline backup recording prepared in case the network fails
- [ ] Solution sketch stays at module level and uses plain language
- [ ] Personal data requirements (children, health, payments) sent to `privacy-specialist`
- [ ] Custom items sent to `estimation-specialist`; no effort or price stated by this role

## Before handoff
- [ ] No must-have rated Planned or Not feasible appears as included scope
- [ ] Dependency table ready for the proposal as separate client costs
- [ ] Promise log complete for every demo and technical message
- [ ] Feasibility of custom or integration-heavy items reviewed by `solution-architect` or `technical-lead`
- [ ] Assumptions, open questions and risks listed
- [ ] Handoff written in `orchestration/handoff-format.md` format with evidence

## Stop and escalate if
- [ ] A free prototype or pilot is requested or already started
- [ ] The prospect wants written uptime, speed or security guarantees
- [ ] A demo would require showing another client's live system or data
- [ ] Credentials are shared in chat for access to a prospect's system
- [ ] Two or more must-haves are Planned or Not feasible
