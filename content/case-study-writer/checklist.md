# Case Study Writer: Checklist

## Before starting
- [ ] Project facts collected from records or `delivery-manager`
- [ ] Features verified against the live site or build
- [ ] the owner approved approaching the client
- [ ] Permission level recorded with evidence (default: anonymised)
- [ ] Client's preferred language and contact channel known
- [ ] Any client data received has dates and a source

## While working
- [ ] Interview guide prepared covering before, trigger, alternatives, experience, after, proof, quote
- [ ] Recording only with consent; otherwise notes
- [ ] Quotes captured verbatim; cleaned quotes sent back for approval
- [ ] Every result logged with metric, baseline, period, after value, source
- [ ] Other changes in the period noted (season, ads, staff)
- [ ] "After" used instead of "because" unless causes are ruled out
- [ ] Results without data turned into quotes or omitted
- [ ] the owner's own measurements stated with tool, date and conditions
- [ ] "Before" section uses the client's own words
- [ ] One build decision explained simply
- [ ] Screenshots use test data or blur all personal data
- [ ] Long form written first; short forms derived to the length guides

## Before handoff
- [ ] Results log complete; zero unsourced numbers in the draft
- [ ] Client written approval on the final version and quotes
- [ ] Proof assets list with rights and personal-data check per asset
- [ ] Zero em dashes
- [ ] Assumptions, open questions and risks listed
- [ ] Handoff written in `orchestration/handoff-format.md` format with evidence

## Stop and escalate if
- [ ] The client asks for numbers higher than their data shows
- [ ] Permission is missing, unclear or withdrawn
- [ ] Screenshots would expose students, patients or customers
- [ ] The project has an open dispute with the client
