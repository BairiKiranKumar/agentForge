# Design Researcher: Checklist

## Before starting
- [ ] Research question states domain, audience and the main action the experience supports
- [ ] Three to five "excellent for this context" criteria written
- [ ] Constraints noted: stack (not assumed), performance budget, scripts and languages, devices, accessibility level
- [ ] Knowledge base searched for existing entries (search terms recorded)
- [ ] Available inspection tools listed (rendering browser, screenshots, fetch only)
- [ ] Access limits noted: logins, paywalls, consent walls (none bypassed)

## While researching
- [ ] At least three independent discovery channels used and recorded per candidate
- [ ] Each shortlisted site opened itself, not only its listing page
- [ ] Inspection level recorded per reference: rendered, source or snippet
- [ ] Rendered inspections cover 1440, 1024, 768 and 375 px, with a capture manifest
- [ ] Type families, scale, line length and rhythm noted from evidence
- [ ] Colour roles and contrast noted from evidence
- [ ] Navigation model and footer composition described
- [ ] Hover, focus, scroll and reduced-motion behaviour checked only where a render allowed
- [ ] "Why it works" follows the chain: need, decision, evidence, principle, limit
- [ ] Inferences labelled `[Inference]`; unsupported claims labelled `[Unverified]`
- [ ] Borrow and do-not-copy notes written for each reference
- [ ] Libraries, WebGL, video and heavy scripts noted for feasibility
- [ ] Licensing and usage terms visible on the source recorded

## Before handoff
- [ ] Set covers at least four visual styles; gaps stated
- [ ] No project-specific or client content in knowledge-base entries
- [ ] No copied text, assets or layouts; quotes short and attributed
- [ ] Entries follow `SCHEMA.md` and use real `verified_on` dates
- [ ] Duplicates merged rather than added
- [ ] Stale or broken entries flagged
- [ ] Research brief leads with the result and lists limits and assumptions
- [ ] Handoff written in the standard format with inspection levels
