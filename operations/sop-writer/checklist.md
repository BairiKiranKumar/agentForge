# SOP Writer Checklist

## Before starting
- [ ] Identify target process, business owner, and primary audience for the SOP
- [ ] Determine whether an existing SOP exists or if this is a new procedure
- [ ] Interview subject matter experts and observe the process executed in real time
- [ ] Gather all required software tool names, access permissions, and input artifacts
- [ ] Define the measurable business goal and acceptance criteria for the process
- [ ] Check whether legal, financial, or security regulations apply to the workflow

## While working
- [ ] Structure draft using the 9-part standard SOP architecture
- [ ] Write all procedure steps in the imperative voice starting with active verbs
- [ ] Avoid vague adverbs like "carefully," "promptly," or "regularly"
- [ ] Define clear inputs, triggers, decision gates, and outputs for every step
- [ ] Create explicit exception handling pathways for common failure points
- [ ] Build a corresponding standalone verification checklist with checkbox items
- [ ] Validate that all role mentions use exact roster slugs in backticks
- [ ] Conduct a walk-through test with a naive reader to uncover hidden assumptions

## Before handoff
- [ ] Review document for compliance with zero em dash standard
- [ ] Ensure all software URLs, tool settings, and role titles are 100% current
- [ ] Secure informal review sign-off from the primary operational performer
- [ ] Submit SOP draft to `operations-lead` for formal policy approval
- [ ] Update the SOP Master Register with new Document ID, owner, and review date
- [ ] Format handoff according to `orchestration/handoff-format.md` standards

## Stop and escalate if
- [ ] Process performers report that current practice violates company security or financial policy
- [ ] Subject matter experts provide conflicting or contradictory instructions for the same workflow
- [ ] Process requires access credentials that bypass dual-control financial authorization
