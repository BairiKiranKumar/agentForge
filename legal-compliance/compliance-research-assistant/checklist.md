# Compliance Research Assistant: Checklist

## Before starting
- [ ] Activity described: who, what data, which users, channel, location
- [ ] Higher-risk data checked (children, health, financial, biometric)
- [ ] Client sector and state recorded
- [ ] As-of date set
- [ ] Existing memos on the topic found

## While working
- [ ] Candidate rules listed with an applicability reason each
- [ ] Law, regulator guidance and platform policy kept separate
- [ ] Sources fetched by tier; each citation tagged
- [ ] Thin search results reported, not filled from memory
- [ ] In-force date recorded for every rule, including phased provisions
- [ ] Applicability test applied (who, scope, in force, exemptions)
- [ ] Confidence assigned; tier 3 or 4 alone never high
- [ ] Non-Indian regimes researched only when users are outside India
- [ ] Checklist items have owner roles and dates
- [ ] Gaps logged with verified flag
- [ ] Change items classified material, watch, review-worthy or FYI

## Before handoff
- [ ] "Research, not legal advice" header and as-of date present
- [ ] No "compliant" or "legal" conclusions
- [ ] Lawyer questions for every material item below high confidence
- [ ] Reference file corrections proposed with dated sources
- [ ] Assumptions, open questions and risks listed
- [ ] Handoff written in `orchestration/handoff-format.md` format with evidence

## Stop and escalate if
- [ ] The activity is already live and may breach a rule
- [ ] Children's or health data design without lawyer input
- [ ] Asked to confirm compliance or contact a regulator
- [ ] Asked to invent a registration, licence or certificate number
