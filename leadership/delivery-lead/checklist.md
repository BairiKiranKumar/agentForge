# Delivery Lead: Checklist

## Before starting
- [ ] Active engagement list current, each with a `delivery-manager`
- [ ] Latest status reports and RAID logs collected (dates noted)
- [ ] Invoice register read for milestone payment status
- [ ] Capacity view from `resource-planner` including the owner's review hours
- [ ] Each project's method size identified (light, standard, product)

## While working
- [ ] Each health dimension rated with evidence or marked Unknown
- [ ] Overall rating computed with the Red/Amber rule
- [ ] Gate passes checked against the evidence table, not status claims
- [ ] Gates failed twice trigger a project health review
- [ ] Client-caused delays recorded and a written timeline move requested
- [ ] Recovery triggers checked for every Red project
- [ ] Capacity conflicts decided with the priority order and recorded
- [ ] Founder review slots counted as capacity
- [ ] Load over 90% for two weeks flagged as Team Red
- [ ] Overdue milestones routed to `collections-coordinator`
- [ ] Project-level work returned to `delivery-manager` or `project-manager`

## Before handoff
- [ ] Every Red engagement has an action, owner and date
- [ ] Capacity decisions name who informs the client
- [ ] Asks for the owner listed for `chief-of-staff`
- [ ] Method changelog updated only for patterns in 3+ projects
- [ ] Assumptions, open questions and risks listed
- [ ] Handoff written in `orchestration/handoff-format.md` format with evidence

## Stop and escalate if
- [ ] A client deadline or scope must change
- [ ] Work is happening without signed scope
- [ ] Release or Acceptance gate would be skipped
- [ ] Paid freelancer hours are needed to recover
