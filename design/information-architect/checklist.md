# Information Architect: Checklist

## Before starting
- [ ] Top three goals and primary conversion written down
- [ ] Audiences or roles listed with their top tasks
- [ ] Requirement IDs received from `requirements-specialist`
- [ ] Existing URL list and analytics collected if restructuring
- [ ] Languages and their URL approach decided (separate trees or toggled content)
- [ ] Platform constraints known (CMS, Next.js routes, single page)

## While working
- [ ] Content inventory has owner and update frequency per item
- [ ] Keep, merge, cut or create decided per item
- [ ] One organisation scheme per level; no mixed schemes
- [ ] Depth fits site type: 1 to 2 levels for small businesses, 2 to 3 for schools and clinics
- [ ] Header has 4 to 7 items ordered by task frequency
- [ ] Primary action visible on mobile outside the menu
- [ ] Footer has address, hours, map, phone, WhatsApp and legal pages
- [ ] Language switch labelled in the target language, not a flag
- [ ] Role-by-section matrix written for apps; no role sees sections it cannot use
- [ ] Labels trace to users' words (reviews, WhatsApp questions, search terms)
- [ ] Regional labels requested from `localization-specialist`; length checked at 375 px
- [ ] Taxonomy terms have scope notes; independent attributes modelled as facets
- [ ] Content model fields have type, required, validation, max length and translatable flag
- [ ] Personal data fields flagged for `privacy-specialist`
- [ ] URLs lowercase, hyphenated, hierarchical, no dates or IDs for public pages
- [ ] No orphan pages; service pages link to the primary action

## Before handoff
- [ ] Every requirement ID maps to a page or section
- [ ] Tree-test tasks and success targets written for `usability-researcher`
- [ ] Redirect map covers every changed public URL with 301
- [ ] Sitemap delivered as ASCII tree, Mermaid diagram and URL map table
- [ ] Assumptions, open questions and risks listed
- [ ] Handoff written in `orchestration/handoff-format.md` format with evidence

## Stop and escalate if
- [ ] A live site is being restructured without a list of current URLs
- [ ] Role permissions are unclear for sensitive records (children, patients, payments)
- [ ] You are asked to change live URLs or redirects directly
