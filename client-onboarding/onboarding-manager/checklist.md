# Client Onboarding Manager: Checklist

## Before starting
- [ ] Won-deal file received from `account-executive`, including promises made on calls
- [ ] Accepted scope baseline linked, with exclusions and third-party services listed
- [ ] Advance status recorded (received, promised with date, or waived by Kiran in writing)
- [ ] Project type chosen so the right access and asset lists are used
- [ ] Onboarding status file opened at `onboarding/<client-slug>/onboarding-status.md`

## Client owners
- [ ] Decision-maker named as a person with a phone number
- [ ] Day-to-day contact named, with expected reply window
- [ ] Account owner for domain, Google and Meta identified (client, relative or old vendor)
- [ ] Post-launch user or admin named for training and handover
- [ ] Kickoff not booked until the decision-maker can attend

## Access
- [ ] Access list trimmed to what the scope needs, nothing extra
- [ ] Each platform has a least-privilege role from the matrix, or an explained exception
- [ ] Each platform has a credential ladder rung chosen; rung 3 and 4 have a reason
- [ ] Platform instructions checked against the current help page (as-of date written)
- [ ] Access log rows include evidence (invite email or screenshot) and a removal date
- [ ] No password, OTP or recovery code appears in any file, note or draft
- [ ] If a password arrived in chat: not copied, client asked to delete and change it, event logged

## Assets
- [ ] Logo requested as SVG or PDF; fallback PNG at least 1000 px wide
- [ ] Photos requested as originals via Drive or Photos link, not WhatsApp
- [ ] Prices, timings and fee structures carry an "as of" date
- [ ] Testimonials have written permission
- [ ] Photos of identifiable children or patients have documented consent, or the question is with `privacy-specialist`
- [ ] No GSTIN, entity name or address invented for legal pages

## Onboarding pack
- [ ] Intake questionnaire received from `requirements-specialist`
- [ ] Kickoff slot options received from `kickoff-facilitator`
- [ ] WhatsApp draft under 150 words with one ask per item and a due date
- [ ] Email draft lists every access and asset item with how to send it
- [ ] Drafts marked for Kiran to send; authorization stays none

## Before handoff
- [ ] Readiness decision follows the scoring rule (no Ready with a blocking item open)
- [ ] Every open item has a client owner and a date
- [ ] Inputs overdue past day 7 flagged to `delivery-manager` as a timeline risk
- [ ] Readiness sign-off written in the section 6 format
- [ ] Handoff to `delivery-manager` includes the access log path and any unbaselined sales promises
- [ ] Assumptions, open questions and risks listed

## Stop and escalate if
- [ ] No decision-maker can be named after two asks
- [ ] Domain or hosting is held by a former vendor who will not transfer
- [ ] Client insists on sending passwords by WhatsApp or email
- [ ] Scope requires migrating children's, patients' or customers' personal data
- [ ] Work is asked to start before the advance without Kiran's written waiver
