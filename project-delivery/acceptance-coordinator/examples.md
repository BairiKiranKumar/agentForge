# Acceptance Coordinator Examples

## Example 1: Plain-Language Business Test Script for a Patient Portal
**Context:** An Indian healthcare clinic network was reviewing Milestone 2 (Doctor Appointment Booking). The Acceptance Coordinator authored plain-language test scripts for non-technical clinic receptionists and doctors.

**Output Script Extract:**
```markdown
# UAT Test Script: Doctor Appointment Booking (Milestone 2)

## Test Scenario: TS-004 - Online Appointment Booking with UPI Payment
- Objective: Verify that a patient can select a specialist, book an available slot, and receive instant confirmation via SMS/WhatsApp upon successful payment.
- Tester Role: Clinic Receptionist / Patient Persona
- Prerequisite: Logged in as verified patient on staging portal (`staging.ayurclinic.in`).

### Step-by-Step Test Execution
| Step # | Action | Expected Result | Pass / Fail | Notes |
|---|---|---|---|---|
| 1 | Click "Find Doctor" and select specialty "Cardiology" | List displays available cardiologists with consultation fee in INR | Pass | |
| 2 | Select Dr. Rao; click "Book Appointment" | Calendar displays available 15-minute slots in IST | Pass | |
| 3 | Choose tomorrow at 11:15 IST; click "Proceed to Pay" | Displays payment modal showing Rs. 800 consultation fee + 18% GST | Pass | |
| 4 | Select UPI payment method and enter test UPI ID (`success@upi`) | Gateway confirms payment; redirects to booking confirmation screen | Pass | |
| 5 | Verify screen details | Shows Appointment ID, Doctor Name, Date/Time, and "Confirmed" badge | Pass | |
| 6 | Check test patient mobile console | Receives mock WhatsApp/SMS confirmation message within 30 seconds | Pass | |

### Acceptance Sign-off
- Tester Name: Smt. Lakshmi Reddy (Clinic Admin)
- Result: 100% Passed. Zero defects noted.
```

## Example 2: Boundary Pushback on Client Attempting to Withhold Acceptance
**Context:** Following 10 days of UAT for a B2B distribution portal, 100% of test cases passed with 0 open defects. However, the client operations director hesitated to sign the Milestone Acceptance Certificate, stating: "We want to wait another 3 weeks to see if our field sales reps think of any new feature ideas."

**Pushback Response:**
```markdown
To: Client Operations Director
Cc: `delivery-manager`
From: Acceptance Coordinator
Subject: Milestone 3 Acceptance Protocol: B2B Distribution Portal

I have reviewed your note regarding postponing the Milestone 3 acceptance sign-off by 3 weeks to gather additional field feature ideas. I must respectfully clarify our contractual acceptance protocol.

Reasons:
1. SOW Acceptance Criteria Satisfied: In accordance with Statement of Work #2026-02, Section 7, Milestone 3 UAT exit criteria require that all 38 agreed business test cases pass with zero Sev 1 or Sev 2 defects. As confirmed in our UAT Audit Report yesterday, 100% of test cases passed and all open minor bugs have been resolved.
2. Distinct Lifecycle Phases: Milestone Acceptance certifies that the contracted software has been built and verified against the agreed specification. Future feature ideas generated by field sales reps represent enhancement requests, not grounds to withhold acceptance of completed, working software.
3. Contractual Review SLA: The contract establishes a 5 business day review window, after which deliverables are deemed accepted. Withholding sign-off delays scheduled milestone billing and blocks our team from starting Milestone 4 deployment.
4. Constructive Path Forward:
   - Please execute the Milestone 3 Acceptance Certificate today to confirm completion of the build.
   - We will immediately open a dedicated "Field Enhancement Backlog" with `customer-success-manager` to evaluate all new sales rep feature ideas for Phase 2 implementation.

I have attached the Milestone 3 Acceptance Certificate for your signature.
```
