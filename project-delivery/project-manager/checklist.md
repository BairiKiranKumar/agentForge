# Project Manager Checklist

## Before starting
- [ ] Review approved Statement of Work (SOW), client deliverables, and hard milestone deadlines
- [ ] Ingest work breakdown structure and effort estimates from `estimation-specialist`
- [ ] Confirm team member allocations and weekly availability with `resource-planner`
- [ ] Initialize project tracking board (Linear / Jira / GitHub Projects) and configure workflow states
- [ ] Establish project RAID log repository and document initial baseline assumptions
- [ ] Schedule recurring sprint rituals (Planning, Standups, Retrospectives) observing IST hours

## While working
- [ ] Review daily asynchronous standup updates by 10:30 IST and identify blockers
- [ ] Actively resolve operational impediments; escalate stagnant blockers after 24 hours
- [ ] Track critical-path tasks daily to detect early schedule divergence
- [ ] Ensure all tasks entering active sprints meet the team Definition of Ready
- [ ] Route all incoming client feature requests immediately to `scope-change-manager`
- [ ] Maintain the project RAID log, updating risk likelihood and mitigation progress weekly
- [ ] Monitor team sprint burndown velocity and adjust task allocations mid-sprint if needed
- [ ] Coordinate with `technical-lead` to ensure technical blockers receive immediate pairing support

## Before handoff
- [ ] Publish weekly Project Status Report every Friday before 17:00 IST with objective RAG rating
- [ ] Verify that completed sprint deliverables are deployed to staging for internal QA
- [ ] Notify `acceptance-coordinator` when a milestone build is ready for client UAT
- [ ] Archive sprint retrospective notes and log continuous improvement action items
- [ ] Confirm zero em dashes are present in any project delivery documentation
- [ ] Format handoff according to `orchestration/handoff-format.md` standards

## Stop and escalate if
- [ ] Critical-path delay exceeds 3 business days, threatening an agreed client milestone
- [ ] Key engineer or designer becomes unexpectedly unavailable with no replacement allocated
- [ ] Client demands major architectural changes mid-sprint while refusing to adjust the launch date
