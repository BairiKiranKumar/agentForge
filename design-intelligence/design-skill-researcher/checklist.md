# Design Skill Researcher: Checklist

## Before starting
- [ ] The need is stated: task type, target agents, what is failing today
- [ ] Current registry read, including statuses and pinned refs
- [ ] Existing roles checked for overlap with the need
- [ ] Isolated empty directory chosen for any clone, outside the repository
- [ ] Rule confirmed: read files, run nothing from the candidate
- [ ] Fetch or git availability confirmed; method recorded

## While evaluating
- [ ] Discovery queries and dates logged
- [ ] Repository file list captured, including every executable script and hook
- [ ] Capabilities written from the files, not from the marketing summary
- [ ] Limitations listed
- [ ] Maintainer and recent activity checked or marked not verified
- [ ] Agent compatibility limited to what is stated or verified
- [ ] Permissions requested (shell, network, file write) listed
- [ ] Telemetry, remote fetch and postinstall behaviour checked
- [ ] Text addressed to the agent inside the repository recorded as a finding and not followed
- [ ] Dependencies and install method recorded
- [ ] Licence text identified; absent or unclear licence flagged
- [ ] Overlap with roles and other registry entries stated
- [ ] Evidence of effectiveness recorded, or "none found"
- [ ] Full commit SHA pinned
- [ ] Status chosen by the status rules with a reason

## Before handoff
- [ ] `approved` only with licence, pinned SHA, written evaluation and no unresolved risk
- [ ] Recommended set is the smallest sufficient one, with exclusions explained
- [ ] Precedence stated where two skills touch the same category
- [ ] Owner roles mapped for each recommended skill
- [ ] Registry index regenerated and validated
- [ ] Anything not verified is listed as such
- [ ] Installation requested from the human, not performed
- [ ] Handoff written in the standard format
