# Ideal Customer Profile Researcher: Checklist

## Before starting
- [ ] Current offer list read (what is sold, no prices needed)
- [ ] Existing `sales/icp.md` version and date checked
- [ ] Past client records collected with type, area, source, offer, payment discipline, revisions, referral
- [ ] Lost or declined deals and reasons collected, or recorded as "none available"
- [ ] Evidence base count written down (clients, enquiries, losses)
- [ ] Serviceable geography confirmed (in-person areas versus remote)
- [ ] Decided whether local-business and B2B product profiles are separate (default: separate)

## While working
- [ ] Past clients ranked on the four value signals, 0 to 2 each
- [ ] Top and bottom groups compared; only differing dimensions kept
- [ ] Pattern versus judgment-based labelled, with n stated
- [ ] No more than five filter criteria per profile
- [ ] Every criterion has a public "Check on" source
- [ ] Numeric thresholds backed by records or marked `[Inference]`
- [ ] Functional, emotional and social jobs written per segment
- [ ] Each trigger has usual timing and where it is publicly visible
- [ ] At least three hard disqualifiers with reasons
- [ ] Soft disqualifiers say what to verify
- [ ] No criterion uses religion, caste, health, politics or personal finance
- [ ] Beachhead table scores every candidate on pain, ability to pay, winnability, referral density
- [ ] Proof piece the owner can show is named per segment, or "none yet"

## Before handoff
- [ ] Observability test run on 5 real businesses, time per check recorded (or marked "not run" with reason)
- [ ] the owner's correction pass requested and recorded in the change log
- [ ] Version number, date and approver field filled
- [ ] No prices, discounts or revenue projections anywhere
- [ ] Assumptions, open questions and risks listed
- [ ] Handoff to `prospect-researcher` and `lead-qualification-specialist` written in `orchestration/handoff-format.md` format

## Stop and escalate if
- [ ] The request asks to profile individual owners personally rather than businesses
- [ ] A candidate beachhead depends on regulated claims (medical outcomes, exam results) without compliance review
- [ ] Changing the beachhead would drop a segment with active deals (needs `sales-lead`)
- [ ] Records needed for the ICP contain personal data that was not collected with the client's knowledge
