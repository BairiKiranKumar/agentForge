# Handover Specialist Checklist

## Before starting
- [ ] Verify that final Milestone Acceptance Certificate has been signed by client sponsor
- [ ] Check with `invoicing-specialist` to confirm all contractual milestone payments are cleared
- [ ] Obtain complete inventory of client code repositories, cloud hosting accounts, and SaaS tools
- [ ] Confirm designated client technical administrator and verify their corporate email identity
- [ ] Verify that production deployment has been completed and certified by `release-engineer`

## While working
- [ ] Compile comprehensive Project Handover Dossier (architecture, runbooks, environment configs)
- [ ] Build minute-by-minute Production Go-Live Cutover Plan with rollback contingency triggers
- [ ] Stage administrative credentials and API keys in an encrypted password vault (1Password/Bitwarden)
- [ ] Transfer primary organization ownership of GitHub/GitLab repositories to client technical lead
- [ ] Transfer primary ownership of cloud hosting (AWS / Vercel), domain DNS, and payment gateways
- [ ] Host live Asset Verification session with client IT lead to test transferred permissions
- [ ] Deprovision or downgrade all studio developer and contractor administrative accounts
- [ ] Document explicit Post-Launch Warranty Period parameters (30 calendar days, SLA response tiers)

## Before handoff
- [ ] Issue Warranty Activation Notice specifying exact start date, end date, and bug reporting rules
- [ ] Secure signed Project Handover & Asset Transfer Certificate from authorized client lead
- [ ] Introduce client team to `client-training-specialist` for scheduled training workshops
- [ ] Archive all handover records, cutover logs, and signed certificates in central legal repository
- [ ] Confirm zero em dashes are present in any handover documentation
- [ ] Format handoff according to `orchestration/handoff-format.md` standards

## Stop and escalate if
- [ ] Project leadership attempts to release root intellectual property while client milestone payments are unpaid
- [ ] Client IT administrator reports failure to access transferred cloud infrastructure or domain DNS
- [ ] Critical third-party SaaS tool cannot be transferred due to vendor enterprise account restrictions
